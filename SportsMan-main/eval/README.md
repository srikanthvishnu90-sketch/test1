# /eval — DEV-ONLY AI evaluation harness

**Not part of the app or any production code path.** Nothing here is imported by
`lib/`; the Flutter build does not include it. These are local Python scripts
(stdlib only — no installs) for measuring listing semantic search and AI cost.

## Files
- `queries.json` — labeled `{query, topic, constraints, expected_listing_ids}`
  entries (generated by `gen_eval.py`). `constraints` are the ground-truth parse
  (price/age/radius/sport/lat-lng); `expected_listing_ids` = catalog listings in
  the topic that SATISFY those hard constraints.
- `gen_eval.py` — regenerates `seed.sql` (a deterministic catalog) and
  `queries.json` (~50 realistic parent queries with hard constraints).
- `setup_local.sh` — stands up local Postgres 17 + pgvector, applies the SHIPPED
  retrieval migration (`20260705_search_listings.sql`) against a minimal schema,
  and loads `seed.sql`.
- `run_hybrid_eval.py` — **the full-pipeline eval.** Runs each query through the
  real `search_listings` SQL and reports **hard-constraint compliance**,
  **recall@10**, and **mean rank**, plus an **assertion suite** (correctness
  gates): zero price/age/radius/sport violations and zero unsupported
  credential/cert terms in the (extractive) explanations. `--selftest` proves the
  gates with no DB.
- `run_eval.py` — the original Stage-0 embedding-similarity eval (cosine only).
- `cost_report.py` — summarizes `ai_audit_log` grouped by **feature** and **day**
  (calls, tokens, est USD). Reads the service-role-only table → needs the service key.

## Full hybrid pipeline eval (Stage 3)
```
brew install postgresql@17 pgvector      # one-time
python3 eval/gen_eval.py                  # -> seed.sql + queries.json
bash    eval/setup_local.sh               # -> local eval DB (host=/tmp/pgs17)
export  EVAL_PGDSN="host=/tmp/pgs17 port=5437 dbname=eval user=postgres"
python3 eval/run_hybrid_eval.py           # prints the table + assertion suite
```
**Baseline note:** the offline run uses CONTROLLED topic embeddings, so semantic
recall is 1.0 by construction (it validates pipeline mechanics + the hard /
credential gates, not real semantic quality). For a real semantic baseline, set
`OPENAI_API_KEY`, backfill real listing embeddings, and substitute
`generate-embedding` vectors — then sweep the ranking weights. See the 3 tuning
recommendations printed at the end of the run.

## Run now, no Supabase (self-test the metric/printing path)
```
python3 eval/run_eval.py --selftest
python3 eval/cost_report.py --selftest
```

## Run against real data (after migration + backfill + functions deployed)
```
# A signed-in user JWT (or the service-role key) lets the eval call generate-embedding:
export EVAL_BEARER="<jwt-or-service-role-key>"
python3 eval/run_eval.py

# Cost report needs the service role (ai_audit_log is service-role-only by RLS):
export SUPABASE_SERVICE_ROLE_KEY="<service-role-key>"
python3 eval/cost_report.py
```
Optional overrides: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `EMBED_FUNCTION_NAME`
(set the last if you deployed `generate-embedding` under a different slug).

## Notes
- Label `expected_listing_ids` from real rows
  (`select id, title, sport_type, skill_level, age_group from programs;`).
- Recall is scored only over queries that have `expected_listing_ids`.
- Never label on price/location/availability/certs/background-check — those are
  structured/deterministic, not semantic (hard rule).
